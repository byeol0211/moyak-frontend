# 소비자 Flutter 앱 작업 현황

Daily 통화 SDK·상담 채팅 클라이언트 추가 이후의 연결 방법과 실제 통화 검증 보류 내역은 [Daily 연동 문서](daily-integration.md)를 참고하세요. 아래 최초 작업 현황 중 화상·채팅 부분은 해당 문서로 보강되었습니다.

기준: 2026-10-16. 키오스크와 백엔드는 이 저장소 작업 범위에 포함하지 않습니다.

> 2026-10-17 업데이트: 자판기 재고·약사 상담·상담 내역·허가서·QR 자판기 연결을 실제 서버 API에 연결했습니다.
> 최신 연동 현황과 Android 빌드 방법은 [프론트엔드 구성](frontend.md)을 기준으로 봅니다.

## 화면 확인 방법

1. 앱 실행 후 권한 안내에서 **계속하기**를 누릅니다. 권한은 실제 기능을 사용할 때 요청합니다.
2. 로그인 화면에서 **회원가입 없이 화면 미리보기**를 선택합니다.
3. 온보딩을 넘기면 서버 요청 없이 홈·지도·챗봇·상담·마이페이지를 둘러볼 수 있습니다.
4. 상단의 미리보기 표시가 있는 동안 예시 데이터만 사용합니다. 실제 처방·결제·기기 연결은 일어나지 않습니다.

미리보기로 확인할 수 있는 흐름:

- 지도 목록 → 상세 재고 → 자판기 선택 → 홈의 `선택됨` 표시.
- 지도 검색창에서 자판기 이름·주소·코드 일부로 전체 자판기 검색(띄어쓰기 무시), 검색어 지우기와 검색 결과 없음 확인.
- QR 화면 → 실제 카메라 인식 / 별도의 `예시 자판기 연결 화면 보기` 버튼.
- 챗봇 질문 입력 → 예시 답변 → 약사 상담 화면에 대화 전달.
- 상담 탭 → 입장 전 기기 확인 → 통화 화면 → 로컬 채팅 입력 → 종료 확인.
- 통화 화면의 입력창을 누르면 영상 위에 반투명 말풍선 표시. 영상이나 접기 버튼을 누르면 입력창만 남고, 다시 열면 대화 유지.
- 자판기 재고 화면은 상품명·분류·수량·품절 상태 조회만 제공. 구매 탭과 상품 구매 동작은 제공하지 않음.
- 상담 화면 상단의 대기·승인·거절 선택 → 결과 화면과 상담 내역·허가서 확인.
- 상담 중 다른 탭으로 이동했다가 복귀해도 진행 화면 유지.
- 상담 내역·허가서 목록 상단에서 예시 데이터·빈 목록·조회 실패 선택.
- 마이페이지 → 로그아웃 확인 → 임시 사용자 정보와 미리보기 기록 초기화.
- 로그인 → 회원가입 → `가입 화면 미리보기 시작` → 아이디 형식 확인·비밀번호 검증·인증 방식 선택.

카메라·QR 인식은 지원 기기 또는 브라우저에서 사용합니다. 웹의 카메라·위치 권한은 HTTPS 또는 localhost 환경이 필요합니다. 권한을 영구 차단했으면 기기/브라우저 설정에서 다시 허용해야 합니다. 위치 서비스가 꺼졌거나 권한을 거부하면 기본 위치로 안내합니다.

## 실행

```sh
flutter pub get
flutter run
```

실제 서버와 연결할 때는 서버 주소를 지정한 뒤 로그인 화면에서 **게스트로 계속하기**를 선택합니다. 챗봇, 지도 목록·재고, 약사 상담, 상담 내역, 허가서가 실제 서버로 동작합니다.

```sh
flutter run --dart-define=API_BASE_URL=https://moyak-backend.onrender.com
```

앱이 제공하는 로그인·회원가입·본인인증 UI는 서버 인증이 아닙니다. API가 준비되기 전에는 성공으로 표시하지 않습니다. 게스트 진입은 임시 사용자 ID만 생성하며, 비밀번호를 저장하거나 전송하지 않습니다.

## 이번 작업

- 아이디 기본값과 무조건 중복확인 성공 제거. 확인 중 아이디를 바꿨을 때 이전 결과가 적용되는 문제 수정.
- 공백을 특수문자로 인정하던 비밀번호 검증 수정. 로그인 필수 입력과 비밀번호 표시 전환 추가.
- 가입 과정의 뒤로가기, 챗봇 대화 전달, 상담 탭 상태 유지 보강.
- 사용자 ID를 `moyak_user_id`로 기기에 저장. 로그아웃 시 삭제.
- 실제 QR 카메라 인식과 QR JSON 형식 검사 추가. 서버 검증 없이 연결 완료로 처리하지 않음.
- 카메라 미리보기·렌즈 전환·마이크 사용 설정, 앱 비활성화 시 카메라 해제 추가.
- 실제 현재 위치 조회와 위치 권한/서비스 실패 안내 추가.
- 이미지 위에 버튼을 얹은 통화 화면을 반응형 위젯 화면으로 교체. 채팅 입력·길이 제한·종료 확인 추가.
- 선택한 자판기와 QR 연결 표시 구분. 구매/결제는 자판기에서 진행하도록 안내.
- 허위 본인인증 완료·등록 카드 표시와 동작 없는 버튼 정리. 재고 신청은 준비 중으로 표시.
- 상담/허가서 조회 재시도와 미리보기의 빈 목록·오류 상태 추가.
- 가짜 앱 상태바 제거(온보딩 속 휴대폰 그림은 설명용). 작은 화면에서 홈·지도 상세·권한 안내 스크롤 처리.
- main.dart에서 마이페이지·상품 목록·재고 신청·하단 메뉴·공통 버튼·테마 분리.

## 백엔드 연결 현황

서버를 새로 구현하지 않고 [백엔드 인수인계 문서](https://github.com/JONGBOK1/moyak-backend/blob/master/docs/flutter-handoff.md)의 계약을 따릅니다. API별 자세한 현황은 [프론트엔드 구성](frontend.md#백엔드-연동-현황)에 있습니다.

| 부분 | 상태 / 연결 위치 |
| --- | --- |
| 지도 상세 재고 | ✅ 연결 (2026-10-17): `data/machine_api.dart` |
| 상담 | ✅ 연결 (2026-10-17): `data/consultation_api.dart`, `ConsultationScreen`. 진행 중 상담 재사용, 3초 상태 확인, 약사 입장 알림, 취소 |
| 화상·채팅 | ✅ 연결 (2026-10-17): 상담 응답의 room_url과 상담 ID를 `AppSession.attachCallRoom`으로 통화 화면에 전달. **실제 통화 검증 전** |
| 상담 내역·허가서 | ✅ 연결 (2026-10-17): 두 화면의 `loadRecords`에 실제 조회 주입 |
| QR | ✅ 연결 (2026-10-17, 기기 확인 완료): 인식한 machineId/token과 사용자 ID를 `POST /vending/scan`으로 전달하고, 성공 후에만 홈을 "연동됨"으로 갱신 |
| 인증·가입 | ❌ 서버 API 없음: `login_page.dart`, `screen_flows.dart`. 현재 임시 ID는 인증 자격 증명이 아님 |

홈의 "자판기 재고 보기(상품 구매하기)" 버튼은 기획 변경으로 제거했습니다(2026-10-17). 미리보기 모드의 상담 상태 선택·예시 허가서·예시 QR 연결은 화면 확인 기능입니다.

## 검증

```sh
flutter analyze
flutter test
flutter build web --no-pub
```

자동 테스트는 입력·QR 파싱·사용자 ID·대화/상담 상태·오류 재시도·작은 화면과 키보드 레이아웃을 검증합니다. Android/iOS 실제 기기의 카메라·마이크 권한, 앱 복귀, 위치 조회, QR 인식은 기기에서 별도 확인해야 합니다. 실제 상담 API 흐름은 `test/consultation_live_test.dart`에서 가짜 서버 응답으로 검증합니다. QR 연결은 갤럭시 S23과 Render 키오스크로 확인했습니다. 실제 영상 통화와 약사 웹 연동은 기기에서 통합 테스트가 필요합니다.
