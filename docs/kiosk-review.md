## 현재 상태

화면과 로컬 시연 흐름을 구현한 단계다. 실제 API, 회원 연동, 결제 및 약품 배출까지 완료된 상태는 아니다.

| 시작·구매 방법 선택 | 화면 및 Navigator 이동 구현 |

`docs/backend_integration.md`에서 실제 서비스와 예시 데이터를 구분한 점, 화면과 서비스 계약을 나눈 점은 이후 연동에 도움이 된다. 1080×1920 기준 캔버스를 비례 축소하는 구성은 세로형 키오스크 시연에 맞춰져 있다. 실제 단말의 해상도·터치 크기·키보드 표시 확인은 별도 필요하다.

## 소비자 앱과 맞춰야 할 부분

소비자 앱의 실제 QR 흐름은 키오스크가 표시한 `{"machine_id":"VM-001","qr_token":"..."}`를 읽어 `POST /vending/scan`에 로그인 사용자 ID와 함께 전달하는 방식이다. 현재 Flutter 키오스크의 임시 QR은 이 흐름과 연결되지 않는다.

우선 키오스크에서 실제 기기 코드 설정, 백엔드 기반 QR 발급·만료·갱신, 연동 결과 조회, 사용자 표시와 화면 전환을 연결해야 한다. 인증 완료 화면의 예시 이름이나 디자인용 기기 문자열을 실제 사용자·기기로 사용하면 안 된다.

그다음 승인된 약 조회와 비회원 상품 구매를 구분하고, 서버의 상품·재고·가격 및 구매 상태를 사용해야 한다. 화면의 버튼 클릭만으로 결제·배출 성공을 판정하지 않고, 실제 결제·배출 상태를 받아야 한다. 구체적인 엔드포인트는 최신 백엔드 계약과 대조해 확정한다.

## 보완할 점과 우선순위

1. **실제 QR 연동:** 앱과 키오스크를 같은 기기 코드·QR 토큰·연동 세션으로 연결한다. 현재 가장 먼저 맞춰야 할 부분이다.
2. **실제 상품·승인 약 조회:** `demo_products.dart`, `DemoCart`를 서비스 응답에 연결한다. `DemoCart`는 기본적으로 예시 상품 2개가 선택되어 있으므로 실제 모드에서는 빈 장바구니로 시작해야 한다.
3. **공통 무조작 초기화:** 현재 10분 타이머는 장바구니 화면에 있고 결제 화면으로 이동하면 취소된다. 결제 화면에는 별도 타이머가 없어 방치 시 초기화가 보장되지 않는다. 실제 연동 전에는 전 화면에 적용되는 세션 만료·장바구니 초기화·시작 화면 복귀를 구현한다.
4. **결제·배출 상태 처리:** 중복 구매 방지, 재고 변경, 결제 취소·실패, 결제 성공 후 배출 실패와 재시도 여부를 백엔드·단말과 합의한다.
5. **문서 갱신:** README가 Flutter 기본 템플릿이다. 실행 방법, 필요한 SDK, 기기 설정, 구현/미연동 상태를 적는다. 연동 문서는 인증 완료가 별도 실행에서만 가능하다고 설명하지만, 코드에는 debug 전용 화면 이동도 있어 최신 흐름으로 맞춰야 한다.

## 검증 제한

이 저장소는 Dart `^3.13.5`를 요구하고 현재 PC의 Dart는 `3.13.4`다. 요구 버전을 임의로 낮추거나 SDK를 변경하지 않았으며, 이번에는 빌드·정적 분석·자동 테스트 통과를 확인하지 않았다. 전체 화면을 실제 단말에서 실행해 본 평가도 아니다.
